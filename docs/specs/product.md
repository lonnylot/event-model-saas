# Event Model SaaS — product design

Status: draft

Locked v1 decisions and spec slices. Living stack/module facts belong in `docs/specs/architecture.md`. Feature work is split into the spec slices listed below; each slice gets its own `docs/specs/features/<slug>.md` and is implemented with `releasing-a-spec`.

## Problem

The Mac app is local-only: one person, one `.eventmodel` file, no accounts. Teams that event-model together currently pass files around. This product is the same Event Modeling canvas, hosted, with sign-in, teams, and turn-taking saves so more than one person can work on one model without silently overwriting each other.

## Decisions (locked)

| Topic | Choice |
|-------|--------|
| Host | Cloudflare Worker + static assets at **event-model.lonnylot.com** |
| Metadata | **D1** (people, sessions, teams, memberships, invites, waitlist emails, event-model rows) |
| Document body | **R2** — current `.eventmodel` JSON only; no version history |
| Auth | Invite-only. Magic link by email. `SITE_ADMIN_EMAIL` is the one exception (may sign in without an invite and becomes site admin). |
| Unknown login | Requester always sees the same “if you have access, check your inbox” copy. Site admin is emailed that address so they can invite. |
| Teams | Site admin creates teams and sends invites. Invited people cannot create teams. Everyone on a team may edit every Event Model on that team. No per-model ACLs. |
| Save conflicts | Optimistic **version check** ([features/model-persistence.md](./features/model-persistence.md)). Explicit Save (⌘S keyboard path is [features/cmd-s-save.md](./features/cmd-s-save.md); the Save button stays [features/editor-shell.md](./features/editor-shell.md)), not autosave. Mismatch → 409; local edits kept until reload or discard. |
| Editor | **Full Mac parity** of editing behavior (not Mac window chrome). Same `.eventmodel` schema as the Mac app. Custom canvas, not a node-graph library. |
| Collab that is out | Live cursors, CRDTs, checkout locks, last-save-wins without a version check |
| Product that is out | Public signup, billing, user-created teams, per-model permissions, document history/restore. Waitlist is not public signup ([features/public-face.md](./features/public-face.md)). |

## People, teams, models

- A **Person** is someone who can sign in. They are not an Actor (an Actor is a block on the canvas).
- A **Team** is created only by the site admin. An Event Model belongs to exactly one Team.
- A Person may belong to more than one Team (each invite adds a membership).
- **Site admin** is the Person whose email matches `SITE_ADMIN_EMAIL` (initially `lonny@lonnylot.com`). They create teams and invite emails onto a team.
- An **Invite** names a team and an email. If that Person does not exist yet, the invite creates them. The invite email contains a magic link (same one-time token as login). If they ignore it, they can still request a login later because the Person now exists. Membership is team-wide: any member may create, open, save, import, and export that team’s Event Models.
- There is no viewer role in v1.

## Sign-in flow

1. GET `/` is the marketing landing ([features/public-face.md](./features/public-face.md)). **Sign in** goes to `/login`. A signed-in GET `/` stays on the landing with **Open app** → `/app`.
2. Login page GET `/login`: email field only. A signed-in GET `/login` 303s to `/app`. Unauthenticated GET `/app` 303s to `/login`.
3. If the email is `SITE_ADMIN_EMAIL` or belongs to an invited Person, send a one-time magic link (TTL 15 minutes, single use).
4. If the email is unknown: do **not** send a login link. Still show the same success copy. Email the site admin: `{address} tried to sign in and has no account`. Do not insert a waitlist row.
5. Rate limit: 5 login submissions per email per hour, and 20 per client IP per hour. Over limit: same success copy, no extra mail.
6. Consuming a valid link sets an httpOnly, Secure, SameSite=Lax session cookie (7 days) and 303s to `/app`. Invalid or used link: heading “This link is expired or already used.” plus **Sign in** to `/login`.
7. After login: if the Person has one team, open that team’s page. If several, show a team picker. Site admin with no teams creates a Team on `/app`. Site admin also sees a Teams admin screen (invite) from the signed-in AppBar `nav` ([features/admin-nav.md](./features/admin-nav.md)). The AppBar logo is the Mark. Editor AppBar includes that signed-in `nav` ([features/app-chrome.md](./features/app-chrome.md)).

## Waitlist

GET `/` has **Join the waitlist** (not Sign up). POST `/api/waitlist` stores the email. Same thanks copy whether the address is new, already waitlisted, or already a Person. Site admin is emailed only when a new waitlist row is inserted. A waitlist row is not a Person, Invite, or Session. They cannot reach `/app` until invited.

Outbound mail uses Cloudflare Email. Login links come from `auth@event-model.lonnylot.com`. Admin notifications go to `SITE_ADMIN_EMAIL`.

## Document flow

- Create: the default Slice on the current team, then open the editor ([features/model-defaults.md](./features/model-defaults.md)). Create is no longer an empty Event Model (valid schema, no slices).
- Import: upload `.eventmodel` JSON; reject if it fails the schema; store the body in R2; metadata in D1 at version 1.
- Open: member-only. Non-members receive **404** (no existence leak). Body is the current R2 object.
- Edit: in-memory document, dirty flag. Undo of New Slice and of Command → Event is [features/canvas.md](./features/canvas.md). Undo of Event → Read Model is [features/undo-connection-event-read.md](./features/undo-connection-event-read.md). Undo Add Command is [features/canvas-rest.md](./features/canvas-rest.md). Undo Add Actor, undo Add Event, undo Add Read Model, undo Add Automation, undo of move, undo of delete, and redo (⇧⌘Z) are [features/undo-rest.md](./features/undo-rest.md). Connection redo restores the undone fromID and toID ([features/redo-connection-pair.md](./features/redo-connection-pair.md)). Nothing is written until Save.
- Save: `PUT` with `{ version, document }`. If D1 version matches: validate schema, write R2 current object, increment version, return the new version. If not: **409** with the current version; client keeps local edits until the person reloads (discarding them) or copies them aside. A failed R2 or D1 write does not increment version.
- Export: download the current R2 JSON as `{title}.eventmodel`. `{title}` is the D1 create title. Filename from JSON `title` stays later.
- R2 key for the current body: `models/{id}.eventmodel`. No `models/{id}/v/{n}` objects in v1.

Two people (or two tabs) on the same model take turns via the version check. There is no lock, presence, or live overlay.

## Error handling

| Case | Behavior |
|------|----------|
| Unknown email at login | Same success copy as a valid request. Site admin emailed. Rate limited. |
| Expired / used magic link | Heading `This link is expired or already used.` **Sign in** → `/login`. No session. |
| Session missing / expired | GET `/login`. In-memory editor state is lost (warn if dirty before navigating away; not across a dead session). |
| Save version mismatch | 409. Keep local edits. Person must reload to get the latest, which discards local, or copy local aside. |
| Illegal connection | Command → Read Model: no edge; the Command listitem shows `A command can't write a read model.` Event → Command: no edge ([features/connection-feedback.md](./features/connection-feedback.md)); the Event Happened listitem shows `An event can't issue a command.` ([features/connection-event-issue-copy.md](./features/connection-event-issue-copy.md)). Leftover Mac pairs refuse with copy on the source ([features/connection-refusals.md](./features/connection-refusals.md)). Highlighting legal targets of one Event and snap-back are [features/connection-feedback.md](./features/connection-feedback.md). Legal target highlight of the last of two Events is [features/port-highlight-hovered-event.md](./features/port-highlight-hovered-event.md). Legal target highlight of the last of two Read Models is [features/port-highlight-hovered-read-model.md](./features/port-highlight-hovered-read-model.md). Undo of Command → Event is [features/canvas.md](./features/canvas.md). Undo of Event → Read Model is [features/undo-connection-event-read.md](./features/undo-connection-event-read.md). |
| Import invalid JSON / schema | Reject; no D1 row; no R2 object. |
| Not a team member | 404 on model routes. |
| Write failure (R2 or D1) | 500. Version unchanged. Client keeps dirty document and may retry Save. |
